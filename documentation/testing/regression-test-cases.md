## 🔐 Регистрационные тест кейсы

### TC-REG-001: Первичная регистрация пользователя как игрока

**Предусловие:** Пользователь не зарегистрирован в системе

**Шаги:**
1. Отправить команду `/start`
2. Выбрать роль "Игрок"
3. Выбрать уровень "Новичок"
4. Выбрать организаторов (минимум одного)
5. Нажать "Завершить регистрацию"

**Ожидаемый результат:**
- Пользователь успешно зарегистрирован
- Отображается сообщение "Отлично! Теперь ты можешь искать игры командой /games"
- Пользователь может выполнять команды игрока

**Критерии приемки:**
- ✅ Пользователь создан в БД с ролью "player"
- ✅ Уровень установлен как "beginner"
- ✅ Связь с организаторами создана
- ✅ Время выполнения < 2 сек

---

### TC-REG-002: Первичная регистрация пользователя как организатора

**Предусловие:** Пользователь не зарегистрирован в системе

- Статус регистрации: "confirmed"

**Критерии приемки:**
- ✅ Регистрация создана в БД со статусом "confirmed"

## 👑 Тест кейсы организатора

### TC-ORGANIZER-001: Создание игры (полный процесс)

**Предусловие:** Пользователь зарегистрирован как организатор

**Шаги:**
1. Отправить команду `/newgame`
2. Выбрать дату (например, завтра)
3. Выбрать время (например, 19:00)
4. Выбрать уровень (например, "Любитель")
5. Выбрать площадку
6. Указать вместимость (например, 12)
7. Указать цену (например, 200 руб)
8. Подтвердить создание

**Ожидаемый результат:**
- Игра успешно создана
- Присвоен уникальный ID
- Статус: "open"
- Отображается сообщение с ID игры
- Игра появляется в списке доступных игр

**Критерии приемки:**
- ✅ Игра создана в БД со всеми параметрами
- ✅ Время выполнения < 10 сек
- ✅ ID уникален и валиден

## 🔄 Процесс выполнения тестирования

### Подготовка к тестированию

1. **Окружение:**
   - Развернуть тестовую среду
   - Убедиться в доступности всех сервисов
   - Очистить БД от предыдущих тестов

2. **Данные:**
   - Создать тестовых пользователей (игроки и организаторы)
   - Создать тестовые игры
   - Подготовить тестовые сценарии

3. **Инструменты:**
   - Подготовить Telegram бота для тестирования
   - Настроить логирование
   - Подготовить средства мониторинга

### Выполнение тестирования

1. **Последовательность:**
   - Выполнять тест кейсы в порядке приоритета
   - Начать с критичных функций
   - Затем перейти к граничным случаям

2. **Документирование:**
   - Записывать результаты каждого TC
   - Фиксировать найденные баги
   - Сохранять скриншоты и логи

3. **Повторное тестирование:**
   - После исправления багов повторить TC
   - Убедиться в отсутствии регрессии

### Завершение тестирования

1. **Анализ результатов:**
   - Подсчитать процент успешных TC
   - Определить критичные баги
   - Оценить готовность к релизу

2. **Отчет:**
   - Составить отчет о результатах
   - Перечислить найденные баги
   - Дать рекомендации
